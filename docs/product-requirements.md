# Mind Vault 个人知识库 Agent 产品需求文档

> 文档版本：V0.1
> 产品阶段：MVP / 需求讨论
> 目标平台：微信小程序（服务端负责解析、索引和 Agent 编排）

## 1. 产品概述

Mind Vault 是一个面向个人的、可引用的知识库与行动型 Agent。用户可以上传书籍、课程、简历、项目文档和面试资料，通过自然语言进行检索、总结、追问和模拟训练。

MVP 聚焦两个高价值场景：

1. 个人资料问答：基于用户上传的文件回答问题，并精确定位原文页码、章节或幻灯片。
2. 面试准备：基于简历、岗位 JD 和项目资料生成问题、模拟面试、追问和复盘。

产品核心承诺：

> 只基于用户授权的资料给出可追溯回答；无法确认时明确说明，不用编造内容代替证据。

## 2. 目标用户与需求

### 2.1 目标用户

- 正在准备校招、社招或转岗面试的个人用户
- 有大量 PDF、课程资料、项目文档和读书资料，需要反复查找的知识工作者
- 希望逐步建立个人长期知识资产的早期用户

### 2.2 核心痛点

- 文件很多，但不知道某个答案在哪一页
- 通用 AI 了解常识，却不了解自己的项目细节
- 复习没有结构，无法根据个人薄弱点持续追问
- 资料、问题、错题和复盘分散在多个工具中

## 3. MVP 范围

### 3.1 P0 必须完成

- 微信登录与个人空间
- 文件上传、解析状态和失败重试
- 支持 PDF、DOCX、XLSX、PPTX、TXT、MD、CSV、JSON
- 文件夹、标签、归档和删除
- ES 关键词检索
- 向量语义检索
- 基础实体和关系抽取，写入 Neo4j
- LangGraph Agent 问题分类和工具路由
- 混合检索与结果重排
- 带来源引用的问答
- PDF 页码、PPT 幻灯片和文档章节定位
- 面试资料集
- 面试题生成、模拟面试、追问和结束复盘
- 会话历史和错题收藏

### 3.2 P1

- 漫画或扫描书籍 OCR
- 多文档对比
- 语音提问和语音面试
- 任务拆解和复习计划
- 错题自动加入复习队列
- Markdown 导出和个人数据导出

### 3.3 暂不做

- 医疗诊断和精确健康建议
- 完整替代 Todo、日历、番茄钟
- 社区、公开知识库和多人协作
- 全自动抓取互联网内容
- 复杂的自动化工作流市场

## 4. 信息架构

微信小程序底部 Tab 建议：

1. **首页**：最近资料、继续训练、快捷提问
2. **知识库**：文件、文件夹、标签、索引状态
3. **面试**：面试资料集、训练入口、错题和进度
4. **我的**：数据、模型、隐私、设置

问答和上传使用全局浮层或明显的快捷入口，不作为底部 Tab，避免导航过载。

## 5. 关键用户流程

### 5.1 上传并建立知识库

1. 用户点击上传
2. 选择文件来源：微信聊天、手机文件、拍照扫描
3. 选择归属资料集和标签
4. 文件进入“上传中”
5. 服务端依次执行解析、切分、实体抽取、ES 索引、向量索引、图谱写入
6. 展示“可问答”或具体失败原因
7. 用户可以进入文件详情查看章节、页数和索引覆盖情况

### 5.2 资料问答

1. 用户输入问题
2. Agent 判断问题类型、范围和复杂度
3. 调用关键词、向量、图谱或混合检索
4. 结果融合并重排
5. 生成回答
6. 展示引用片段和来源位置
7. 用户可点击“查看原文”、继续追问、纠错或收藏

### 5.3 模拟面试

1. 选择资料集、目标岗位和训练模式
2. Agent 生成第一道问题
3. 用户文字或语音回答
4. Agent 基于简历和项目资料进行追问
5. 用户主动结束或完成题目数
6. 输出维度化反馈、证据引用和下一步复习建议

## 6. 功能需求

### 6.1 文件管理

| 功能 | 需求 |
|---|---|
| 上传 | 单文件建议不超过 100MB；大文件显示进度，服务端异步处理 |
| 解析状态 | 待处理、解析中、可问答、部分成功、失败 |
| 文件详情 | 文件名、类型、大小、页数、章节、更新时间、索引状态 |
| 组织 | 文件夹、标签、资料集；一个文件可加入多个资料集 |
| 删除 | 删除原文件、文本片段、向量和图谱关系，提供二次确认 |
| 预览 | PDF 页码、PPT 页、文档章节；表格定位到工作表和单元格范围 |

### 6.2 检索与 Agent

Agent 节点建议：

```text
接收问题
  -> 识别资料范围
  -> 分类问题类型
  -> 复杂度判断
  -> 选择检索工具
  -> 执行检索
  -> 结果融合与重排
  -> 证据充分性判断
  -> 生成回答
  -> 保存会话与反馈
```

问题类型：

- 精确定位：人名、原句、数字、文件名
- 语义理解：总结、解释、改写
- 关系推理：人物关系、因果、多跳路径
- 对比分析：跨文件、跨章节比较
- 面试训练：出题、追问、评价

路由原则：

- 精确实体或原文措辞：ES + 向量
- “谁和谁、关系、前因后果”：Neo4j + 向量
- 跨文件比较：三路检索
- 复杂度低且范围明确：单路检索，控制成本
- 证据不足：扩大召回、请求澄清或返回“不足以确认”

结果融合建议使用 RRF 或加权融合，随后使用 reranker。不要以单一向量相似度直接决定最终答案。

### 6.3 引用与原文定位

每个引用至少包含：

- 文件名
- 章节或标题
- 页码 / 幻灯片编号 / 工作表
- 原文片段
- 可点击定位参数

回答中区分：

- **原文事实**：来自资料的直接内容
- **综合判断**：对多个证据的归纳
- **推测**：证据不足时的合理推断

### 6.4 面试准备

资料集可包含：

- 简历
- 岗位 JD
- 项目 README
- 设计文档
- 代码说明
- 复盘记录

训练模式：

- 快速问答
- 项目深挖
- 技术面试
- 行为面试
- 岗位定制模拟

反馈维度：

- 事实准确性
- 结构完整性
- 技术深度
- 量化结果
- 表达清晰度
- 是否引用了真实项目证据

## 7. 移动端页面需求

### 首页

- 问答输入框作为首要操作
- 最近使用的资料集
- 最近上传文件及解析状态
- “继续面试”入口
- 最近错题或待复习内容

### 知识库页

- 文件列表
- 搜索、文件夹和标签筛选
- 上传按钮
- 文件状态筛选
- 进入文件详情和原文预览

### 问答页

- 消息流
- 引用折叠卡片
- 原文定位按钮
- 当前资料范围提示
- 重新生成、收藏、反馈
- 输入框和语音入口

### 面试页

- 当前训练资料集
- 训练模式选择
- 开始训练
- 最近训练记录
- 错题和薄弱点

### 原文预览页

- 页码或章节导航
- 高亮命中片段
- 上下文展开
- 返回问答

## 8. 非功能需求

### 性能目标

- 首页首屏：P95 小于 2 秒
- 已完成索引的简单问答首 token：P95 小于 5 秒
- 普通问答完成：P95 小于 15 秒
- 文件上传后 30 秒内开始解析
- 解析任务可重试且幂等

### 可靠性

- 所有索引任务写入任务表
- 失败任务记录阶段和错误信息
- Agent 工具调用设置超时、重试和最大步数
- 无证据时禁止生成确定性结论

### 隐私

- 用户数据按 user_id 隔离
- 文件、文本、向量、图谱均支持级联删除
- 明确第三方模型是否保存数据
- 支持导出和彻底删除
- 健康、简历和项目资料默认私有

## 9. 数据模型建议

```text
User
Document
DocumentVersion
DocumentSection
DocumentChunk
Dataset
Tag
Entity
Relation
Conversation
Message
Citation
InterviewSession
InterviewQuestion
InterviewAnswer
ReviewItem
```

DocumentChunk 是三个检索系统的共同最小单位。原文定位信息必须在切分时保留，不能在生成回答时再推算。

## 10. 验收标准

- 上传一个含目录的 PDF 后，能够按页检索并回答
- 查询专有名词时，ES 能找回包含原词的片段
- 使用同义表达提问时，向量检索能找回相关片段
- 对人物关系问题，图谱能够返回实体和关系路径
- 混合检索结果比任一单路结果更完整
- 每个关键回答至少有一个可点击来源
- 点击引用后能打开对应页或章节
- 面试 Agent 能基于用户项目资料追问，而非生成通用问题
- 删除文件后无法从问答、向量或图谱中再次召回
- 解析失败能够展示原因并支持重试

## 11. 产品指标

MVP 阶段关注质量而不是活跃规模：

- 首次上传成功率 ≥ 95%
- 可问答文件解析成功率 ≥ 95%
- 有证据回答占比 ≥ 90%
- 引用定位正确率 ≥ 95%
- 用户对回答“有帮助”的反馈 ≥ 70%
- 面试训练完成率 ≥ 40%
- 用户一周内再次使用同一资料集的比例 ≥ 30%

## 12. 技术落地建议

现有 NestJS 后端可以继续作为 API 层。建议补充：

- 对象存储：原始文件和 PDF 页面预览
- PostgreSQL：用户、文档、任务、会话和面试数据
- Elasticsearch：BM25 和元数据过滤
- 向量库：可先使用 Elasticsearch dense_vector，规模扩大后再拆分
- Neo4j：实体、关系和来源 chunk
- 异步队列：解析、OCR、Embedding、图谱抽取
- LangGraph：Agent 状态、路由、工具调用和检查点

微信小程序只负责交互和展示，长耗时解析及 Agent 任务必须异步化。
