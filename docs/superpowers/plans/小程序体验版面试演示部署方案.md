# 小程序体验版面试演示部署方案

## Context

小程序正式上架必须先完成备案（自 2023-09-04 起未备案不可上架），周期长；但「体验版」不需要备案——代码上传后在「小程序后台 → 版本管理」直接设为体验版即可，不经过审核。因此面试演示的路径是：**后端部署到公网 + 小程序发体验版**，完全绕开备案等待。

用户已确认四项决策：
1. 部署方式走 **GitHub Actions → 阿里云 ACR → ECS**（沿用 [aliyun-github-actions-deployment.md](file:///Users/susucain/开发/mind-vault/docs/aliyun-github-actions-deployment.md) 的既有设计）
2. **升级现有 ECS** 到 4C8G 以上
3. 小程序登录**实现微信 code2Session**（不用 dev-login）
4. 演示前把**本地数据迁移到云端**，让小程序一进去就有内容

目标：面试时自己手机扫码打开体验版，完整跑通「登录 → 上传资料 → 检索问答 → 面试训练 → 复习」。

## 调研结论（决定方案的硬约束）

- **六套中间件全是启动硬依赖，一套都省不掉**：
  - PostgreSQL / pgvector — [app.module.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/app.module.ts#L60-L94) `TypeOrmModule.forRootAsync`
  - MongoDB — 同文件 `MongooseModule.forRootAsync`
  - Neo4j — [knowledge-graph.service.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/graph/knowledge-graph.service.ts#L16-L34) `onModuleInit` 里建约束
  - RabbitMQ — [document-progress.service.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/document/document-progress.service.ts#L28-L40) 让 **API 进程**在 `onModuleInit` 就连
  - Elasticsearch — `DocumentModule` 注入 client，`RetrievalService` 用 ES kNN 做向量检索
  - 对象存储（S3/RustFS → 迁阿里云 OSS）
  - 合计约 5GB 内存 ⇒ 2C2G 的 ECS 不够，必须升配
- **`NODE_ENV=production` 会禁用 dev-login**：[auth.service.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/auth/auth.service.ts#L42-L45) 的 `devLoginEnabled` 默认 `NODE_ENV !== 'production'`，命中即抛 403。这是「选微信登录」的直接原因，也意味着生产环境不能依赖 dev-login。
- **后端暂无 `/auth/wechat`**：[auth.controller.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/auth/auth.controller.ts) 只有 login / register / dev-login；小程序 [auth.ts](file:///Users/susucain/开发/mind-vault/mind_vault_miniapp/services/auth.ts#L17-L40) 的 `wechatLogin()` 目前是死代码，但**流程已经写好**（`wx.login` → `POST /auth/wechat`），补后端即可。
- **[main.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/main.ts) 没有 `enableCors`**。小程序用原生请求不受 CORS 约束，本期不用动；将来 Web 端独立域名部署时才需要。
- **小程序需要两个合法域名**：`request`（所有接口 + SSE）和 `uploadFile`（[documents.ts](file:///Users/susucain/开发/mind-vault/mind_vault_miniapp/services/documents.ts#L53-L113) 用 `wx.uploadFile`）。域名必须 HTTPS、ICP 已备案、且**不能带端口** ⇒ Nginx 必须监听 443。
- **SSE 在真机上的行为必须实测**：`wx.request` + `enableChunked` 在开发者工具与真机不同，Nginx 必须关闭响应缓冲。
- 部署产物**目前都不存在**：`mind_vault_api/Dockerfile`、`deploy/`、`.github/workflows/` 均需新建。

## 阶段 1：后端支持微信登录

- `src/config/configuration.ts`：新增 `wechat: { appId, appSecret }`，读 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`。
- `src/auth/entities/user.entity.ts`：新增 `wxOpenId` 字段（`name: 'wx_open_id'`, `varchar(64)`, nullable, unique）。
- 新增迁移 `src/migrations/<ts>-add-wechat-open-id.ts`：`ALTER TABLE kh_user ADD COLUMN wx_open_id VARCHAR(64)` + 唯一索引。**必须同时加进 [app.module.ts](file:///Users/susucain/开发/mind-vault/mind_vault_api/src/app.module.ts#L86-L91) 的 migrations 白名单**，否则不会执行（仓库既有约定）。
- 新增 `src/auth/dto/wechat-login.dto.ts`（`code: string`）。
- 新增 `src/auth/wechat.service.ts`：封装 `GET https://api.weixin.qq.com/sns/jscode2session`，只用 Node 内置 `fetch`，不引新依赖。失败/`errcode` 非 0 时抛 `UnauthorizedException`，不透传微信原始报文。
- `AuthService` 新增 `loginWithWechat(code)`：openid 已存在 → 签发；不存在 → 用 `nextSnowflakeId()` 建用户（`username` 用 `wx_<openid 前 12 位>`，`passwordHash` 存不可用占位）后签发。复用既有 `issueSession()`。
- `AuthController` 新增 `@Post('auth/wechat')`。
- 单测：`wechat.service.spec.ts` + `auth.service.spec.ts` 补 `loginWithWechat` 分支（沿用仓库既有的入参感知 mock 写法）。

## 阶段 2：后端容器化

- 新增 `mind_vault_api/Dockerfile`：多阶段（`deps` 装依赖 → `build` 跑 `nest build` → `runtime` 只带 `dist` + `node_modules`），基础镜像用 `node:22-slim`。镜像同时承载 API（`node dist/main`）与 Worker（`node dist/worker`），靠启动命令区分 —— 与部署文档第 10 节一致。
- 新增 `mind_vault_api/.dockerignore`（排除 `node_modules`、`dist`、`volumes`、`.env`、`coverage`）。
- 注意 `pgvector/pgvector:0.8.3-pg16` 与 `./init-scripts/postgresql` 的挂载必须保留，否则 `vector` 扩展不会被创建。

## 阶段 3：生产编排与 Nginx

- 新增 `mind_vault_api/deploy/compose.prod.yml`：只保留 `api` / `worker` / `postgres` / `mongodb` / `rabbitmq` / `es` / `neo4j`；移除 `pgadmin` / `mongo-express` / `kibana` / `rustfs`（改用 OSS）；数据库与中间件**不映射宿主端口**，全部只在内网；所有服务 `restart: unless-stopped`；给 ES / Neo4j / API / Worker 设置 `deploy.resources.limits.memory`；使用独立 Compose 项目名，避免影响 ECS 上已有项目。
- 新增 `mind_vault_api/deploy/nginx.conf`：443 + HTTPS，反代到 `api:3000`。**SSE 关键项**：
  - `proxy_buffering off;`、`proxy_cache off;`
  - `proxy_http_version 1.1;`、`proxy_set_header Connection "";`
  - `proxy_read_timeout 300s;`（长连接问答/面试流）
  - `client_max_body_size 100m;`（上传大文件）
  - `location /v1/` 透传前缀
- 新增 `mind_vault_api/deploy/deploy.sh`：接收镜像 SHA → 更新 `.env` 的 `IMAGE_TAG` → 登 ACR → 拉镜像 → `docker compose up -d` → 轮询 `/v1/health`。密码不打印到标准输出。

## 阶段 4：GitHub Actions

- 新增 `.github/workflows/backend-deploy.yml`：`push main`（`paths: mind_vault_api/**`）+ `workflow_dispatch`；步骤为 install → `pnpm --filter` 测试 → build & push 镜像（SHA 标签 + `main` 别名）→ SSH 到 ECS 执行 `deploy.sh`。
- 需要你在 GitHub 仓库配置 Secrets：`ACR_REGISTRY` / `ACR_NAMESPACE` / `ACR_REPOSITORY` / `ACR_USERNAME` / `ACR_PASSWORD` / `ECS_HOST` / `ECS_PORT` / `ECS_DEPLOY_USER` / `ECS_DEPLOY_SSH_KEY` / `ECS_KNOWN_HOSTS`。

## 阶段 5：ECS 手工操作（你执行，我给命令）

顺序按部署文档第 4、8、9 节：升配 ECS → 建 ACR 实例/命名空间/私有仓库 → 建两个独立 RAM 凭据 → 建 OSS Bucket 与专用 RAM 凭据 → 域名 A 记录 + 安全组放行 80/443 → 装 docker/compose/nginx/certbot → `usermod -aG docker deploy` → 建 `/opt/mind-vault` → 写生产 `.env` → 申请 Let's Encrypt 证书。

生产 `.env` 关键项（除基础设施与模型 Key 外）：
```env
NODE_ENV=production
JWT_SECRET=<随机长串>
DEV_AUTH_ENABLED=false
WECHAT_APP_ID=wxd529e9f2fed1568d
WECHAT_APP_SECRET=<小程序后台获取>
STORAGE_ENABLED=true
S3_ENDPOINT=https://oss-cn-hangzhou-internal.aliyuncs.com
```

## 阶段 7：数据迁移（让演示有内容）

顺序很重要，**先登录拿 ID、再迁数据**：

1. 体验版部署好之后，先用你的微信在小程序里登录一次，拿到云端 `kh_user` 里为你创建的用户 id。
2. 本地导出：`pg_dump` 出 `knowledge_hub`，导云端后逐表 `UPDATE ... SET owner_id = <新 id> WHERE owner_id = 10001`（表清单从 `src/**/entities/*.entity.ts` 里的 `owner_id` 列确认）。
3. MongoDB 集合同样按 `ownerId` 改写后导入。
4. 原文件上传到 OSS，路径沿用现有 `rustfs.service.ts` 的对象 key 规则。
5. **ES 索引与 Neo4j 图谱不迁移**，在云端重新上传/重跑文档摄取来重建 —— 这两者本就是从 PG 派生的，重建比改写 ownerId 更干净。

## 验证方式

- 后端：`pnpm --filter mind-vault-api test` + `lint` + `build`，容器内 `curl http://localhost:3000/v1/health`
- 登录：`curl -X POST https://api.<your-domain>/v1/auth/wechat -d '{"code":"<真机 code>"}'` 返回 `accessToken`
- 端到端：体验版真机跑「登录 → 上传一份 PDF → 等摄取完成 → 发起问答看引用 → 创建面试会话 → 复习列表」
- 部署可回滚：`./deploy.sh sha-<上一个稳定提交>`

## 风险

- **ECS 升配要重启**，会影响上面已跑的其他项目；建议挑低峰期做。
- **JWT 无状态**：`JWT_SECRET` 变更会让所有已登录会话失效。
- **迁移只向前不向后**：`migrationsRun: true`，发版前先 `pg_dump` 备份。
- **演示成本**：问答/面试每轮都真实调模型，面试前先自己跑一遍确认额度够。
- **兜底**：无论如何录一段完整流程视频。体验版当场扫码失败（网络、微信版本、体验成员）时这是唯一保险。
