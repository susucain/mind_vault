# 文档入库终态展示与轮询设计

## 目标

修复文档上传完成后因模型供应商限流或配额不足而失败时的错误展示和持续状态请求。

上传成功仅表示源文件已保存。入库主流程（解析、切分、向量化、索引）和图谱流程是后续异步任务，必须分别展示。

## 已确认的展示规则

- 入库主流程失败时，隐藏主入库进度文本和进度条，避免显示没有实际处理进展的 `0/N`。
- 图谱状态仍展示。图谱任务尚未创建时显示 `NOT_STARTED 0/0`，表明该步骤没有开始而非丢失。
- 失败卡片展示失败阶段、可读的错误消息和“重试解析”操作。
- 文件上传完成仍保留为已完成状态，但不与入库主进度并列为两个处理进度。

## 状态机与数据流

1. 小程序完成 `POST /documents/upload` 后记录文档 ID，开始查询 `GET /documents/:id/status`。
2. Worker 依次写入 `PARSING`、`PARSED`、`CHUNKING`、`EMBEDDING`、`INDEXING`、`READY` 或 `FAILED`。
3. 每次状态写入发布 `document.progress` SSE 事件。失败写入必须同样发布终态事件。
4. 小程序收到事件后，仅在当前上传文档仍处于非终态且没有在途查询时，刷新状态。
5. `READY`、`FAILED`、`DELETED` 为主入库终态。收到任一终态后，取消该文档的轮询定时器；后续 SSE 事件不得重新启动状态查询。
6. `READY` 且图谱仍为 `PROCESSING` 时不再轮询主入库状态，改由 SSE 刷新列表/图谱展示，避免图谱进度延长主入库轮询。

## 后端变更

- 在 `DocumentIngestionWorker.process` 的失败分支保存失败状态后发布 `document.progress` 终态事件。
- 终态事件包含当前阶段、`FAILED` 状态、当前进度和错误信息对应的持久化状态，供 API 或 SSE 消费方刷新。
- 不将供应商 `429 MODEL_RATE_LIMIT` 误报为文件解析错误；保留原始错误消息，错误码从通用 `PARSE_FAILED` 改为与失败阶段相符的分类。

## 小程序变更

- 提取主入库终态判断与“是否展示主进度”判断，使 `library.ts` 的轮询、SSE 回调和 WXML 使用相同规则。
- 为状态查询设置在途保护和失效令牌，防止多个 SSE 事件并发触发相同文档的 `GET status`。
- 终态到达时停止轮询；SSE 回调忽略当前文档的终态后续事件。
- WXML 在失败时隐藏 `stageProgress` 的文本与进度条，始终保留非空 `graph` 的状态行，包括 `NOT_STARTED 0/0`。

## 测试

- 后端 worker 测试：向量化阶段异常后，任务和文档写为失败，并发布一条 `FAILED` 进度事件。
- 小程序纯函数测试：失败状态不展示主入库进度，但图谱 `NOT_STARTED 0/0` 仍可展示。
- 小程序页面行为测试：终态不会调度下一次查询，且多个 SSE 事件只能驱动一个在途状态查询。

## 非目标

- 不改变模型账户、配额、限流策略或自动重试次数。
- 不改变图谱任务的创建时机或图谱 `0/0` 的语义。
