# 问答会话资料范围选择设计

## 背景

问答页当前存在三个问题：

1. 会话内切换资料集只更新小程序本地状态，没有更新后端会话的 `datasetIds`，导致下一次提问仍按旧资料范围检索。
2. 新会话默认使用全部资料集，但 UI 只把所有资料集逐个展示出来，没有显式的“全部资料”选项。
3. 资料集较多时，横向滚动标签不适合查找目标资料集；需要采用类似 Library 页的搜索选择器。

本次改动只针对问答页的资料范围选择和会话持久化，不改变已有消息、检索、引用和会话历史语义。

## 目标

- 在同一会话内支持多选资料集，并让选择结果持久化到当前会话。
- 提供“全部资料”快捷选项。
- 新会话默认选择“全部资料”。
- 已有会话重新打开时恢复其保存的资料集范围。
- 使用方案 B 的 UI：顶部显示当前范围标签，点击“切换”打开选择面板。
- 资料集很多时可按名称搜索。
- 保存资料范围失败时不丢失用户正在编辑的选择，并阻止带有不确定范围的提问。

## 非目标

- 不改变资料集、文档或检索接口。
- 不为每条消息增加独立资料范围字段。
- 不把历史消息按资料集重新生成或迁移。
- 不引入新的全局资料集状态管理框架。

## 术语和数据语义

- **全部资料**：当前用户资料集列表中的全部资料集 ID。
- **自定义范围**：一个或多个资料集 ID。
- 前端始终向会话接口传递具体的 `datasetIds` 数组；“全部资料”不使用空数组表示。
- 当前后端检索层仍将空数组视为“不添加资料集过滤”，但本功能不会依赖该隐式语义。
- 资料集列表为空时，问答页继续显示空状态，不允许创建可发送的问答范围。

## 用户界面

### 顶部范围摘要

问答页标题下方使用一个资料范围控制区域：

- 全部资料：显示 `全部资料`
- 只选一个：显示该资料集名称及文档数量（如可用）
- 选择多个：显示 `已选 N 个资料集`
- 显示一个“切换”按钮，点击后打开资料范围面板

不再在顶部横向渲染所有资料集 chip，避免资料集数量增长导致页面不可用。

### 资料范围面板

面板沿用 Library 页的选择器视觉和搜索模式，使用底部弹层承载：

- 搜索输入框
- “全部资料”快捷项
- 按当前搜索结果展示资料集
- 每项展示选中状态
- “取消”关闭面板并丢弃本次临时修改
- “完成”提交本次临时选择

“全部资料”行为：

- 点击时选中当前用户的全部资料集。
- 当全部资料集均已选中时，显示为选中状态。
- 在全选状态下取消任意一个资料集后，转为自定义多选状态。
- 在自定义状态下重新点击“全部资料”恢复全选。

搜索只影响列表展示，不影响已经选中的资料集。搜索结果为空时仍保留已选数量和“全部资料”入口。

### 保存交互

打开面板时复制当前会话范围到临时集合 `draftDatasetIds`。

- 勾选或取消资料集只修改临时集合。
- 点击“完成”时，若临时集合为空，提示“请至少选择一个资料集”，不发请求。
- 有效选择调用会话资料范围更新接口。
- 请求进行中禁用列表和按钮，避免并发更新。
- 成功后关闭面板，并同步：
  - `selectedDatasetIds`
  - 当前会话对象的 `datasetIds`
  - 范围摘要
- 失败后面板保持打开，临时选择保留，显示错误提示，允许重试或取消。
- 发送按钮在保存期间禁用。

## 后端接口

新增：

```http
PATCH /conversations/:id
Content-Type: application/json

{
  "datasetIds": ["dataset_1", "dataset_2"]
}
```

响应返回更新后的会话对象：

```json
{
  "id": "conversation_1",
  "title": "资料问答",
  "datasetIds": ["dataset_1", "dataset_2"],
  "createdAt": "...",
  "updatedAt": "..."
}
```

### 校验和授权

- 复用当前认证和限流守卫。
- 会话必须属于当前用户，否则返回现有的 not found 行为。
- `datasetIds` 必须是非空字符串数组，最多 20 个，沿用创建会话的上限。
- 每个 ID 必须属于当前用户且未删除；不存在或不属于当前用户的 ID 导致请求失败，不能静默保存部分范围。
- 服务端去重，保持客户端提交中首次出现的顺序，确保重复提交具有幂等行为。

### 服务端问答行为

现有流式接口不变。`ChatService.ask` 每次开始时读取当前会话记录的 `datasetIds`，因此更新接口成功后，下一次提问自然使用新范围。

正在进行的提问继续使用开始时读取的会话范围；资料范围更新不取消当前流。UI 在发送中不允许打开或提交范围面板，避免用户误以为当前流已经切换范围。

## 小程序状态和数据流

问答页新增或调整以下状态：

- `selectedDatasetIds`：当前会话已保存的范围
- `draftDatasetIds`：面板打开后的临时范围
- `showDatasetSelector`：范围面板是否显示
- `datasetQuery`：搜索关键词
- `datasetResults`：搜索结果
- `savingDatasetScope`：范围更新请求状态

初始化：

1. 并行加载资料集和会话。
2. 创建新会话时传入全部资料集 ID。
3. 打开已有会话时使用会话返回的 `datasetIds`，不再用资料集列表覆盖它。
4. 当旧数据出现空 `datasetIds` 时，按兼容策略在 UI 中展示为“全部资料”，但在用户点击“完成”或发送前可规范化为当前全部资料集 ID。

搜索：

- 沿用 `listDatasets({ name, pageSize: 20 })`。
- 保留 Library 页的输入防抖和请求清理模式。
- 搜索请求返回后只更新 `datasetResults`，不覆盖 `draftDatasetIds`。

会话切换：

- 切换会话前停止未完成的当前流，沿用现有会话切换保护。
- 打开目标会话后加载其历史消息和资料范围。
- 如果范围面板打开，切换会话应先关闭面板并清空临时状态。

## 错误处理

- 更新失败：保留面板和草稿，展示请求错误，不修改当前已保存范围。
- 搜索失败：保留当前草稿，展示搜索错误，可继续重试；不影响已保存范围。
- 资料集列表加载失败：沿用现有页面错误状态。
- 当前已保存的资料集被删除：初始化时从可用资料集中清理无效 ID；若清理后为空，按全部资料兼容处理并提示用户确认保存。
- 发送时若会话范围保存请求仍在进行，阻止发送并提示“正在保存资料范围”。

## 测试策略

### API 单元测试

- 更新属于当前用户的会话资料范围并返回更新后的会话。
- 拒绝空数组、超过 20 个 ID 和不属于当前用户的资料集；重复 ID 去重后保存。
- 更新不存在或不属于当前用户的会话返回 not found。
- `ask` 在资料范围更新后向 agent 传递新的 `datasetIds`。

### 小程序单元测试

- 全部资料状态等于当前资料集 ID 集合。
- 点击“全部资料”选中全部；取消任一项后变为部分选择；再次点击恢复全选。
- 搜索结果变化不影响已选集合。
- 点击完成调用更新接口，成功后同步会话和摘要。
- 更新失败保留草稿和面板，不覆盖当前已保存范围。
- 新会话传递全部资料集 ID，已有会话使用会话自身的 ID。

### 手工验收

1. 创建新会话，确认顶部显示“全部资料”，发送问题并确认后端使用所有资料集。
2. 打开切换面板，搜索并选择两个资料集，完成保存后发送下一条问题，确认只在这两个资料集中检索。
3. 取消其中一个资料集，确认下一次问题使用剩余范围。
4. 重新进入该会话，确认范围仍保持。
5. 选择“全部资料”，确认所有资料集恢复选中。
6. 模拟更新接口失败，确认草稿不丢失且不会发送未保存范围。
